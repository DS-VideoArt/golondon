# איסוף חדשות ל"מה חדש בלונדון", שלב 0

בטא בטוחה: אוסף מועמדים ממקורות רשמיים וחינמיים, מסווג, מדרג ובודק עובדות, וכותב **טיוטות לבדיקה בלבד**.
אין פרסום, אין כתיבה לקבצי האתר, אין מודל שפה, אין תשלום ואין תזמון פעיל.

## הרצה

```bash
python3 news_pipeline/run.py --slot manual
```

דגלים עיקריים:

| דגל | מה עושה |
|---|---|
| `--slot morning\|evening\|manual` | שם החלון. משפיע על run_id ועל `--respect-slot` |
| `--respect-slot` | יוצא בלי לעשות דבר אם עכשיו לא 08:00 או 19:00 בשעון ישראל |
| `--fixtures DIR` | קורא קבצים מקומיים במקום רשת |
| `--now ISO` | זמן ריצה קבוע, לבדיקות ולשחזור |
| `--sources a,b` | רק מקורות מסוימים |
| `--out DIR` `--state DIR` | תיקיית פלט ותיקיית זיכרון. ברירת מחדל בתוך news_pipeline, ושתיהן ב-.gitignore |
| `--no-state-write` | לא מעדכן את הזיכרון בין ריצות |
| `--json` | שורת סיכום JSON בסוף, לחיבור ל-DS AI Operations |
| `--decide ID=approve\|reject` | החלטת בעלים על פריט בתור (מזהה מלא או תחילית ייחודית). מעדכן רק את הזיכרון המקומי, בלי איסוף |

קודי יציאה: 0 הושלם (כולל "אין מה לפרסם"), 1 שגיאת שימוש, 2 כל המקורות נכשלו.
`--mode publish` לא קיים ומחזיר 1.

## פלט

`out/<run_id>/`:

* `drafts.json`: הפריטים שנכנסו לתור בריצה הזו, לפי סדר עדיפות, ולצידם `pending` (ממתינים מריצות קודמות), `backlog` (מחוץ למכסה) ו-`left_queue`. לכל טיוטה: עובדות עם evidence, ניקוד מפורט, הסיבות, בדיקת עובדות, הצעה לאייטם במבנה whats-new.json שבה כל שדה עברי ריק, ורשימת missing_fields.
* `decisions.json`: כל מועמד שנבדק, כולל הנפסלים והסיבה העיקרית.
* `report.md`: דוח קריא בעברית.
* `run.json`: תקציר, מצב כל מקור, יומן הבקשות, ומבנה handoff עם `requires_owner_approval: true` ו-`publish_allowed: false`.

## סדר עדיפויות ותור

* **כשירות** (`scoring.py`): האם הפריט ראוי בכלל לטיוטה. שערי פסילה ועצירה ורף רלוונטיות.
* **עדיפות** (`priority.py`): כמה הפריט משנה למטייל. השפעה מעשית (עד 40), עניין לתייר (עד 40),
  דחיפות (עד 10) ואמינות (עד 10). לשיבוש תחבורה יש רק השפעה מעשית ולאירוע רק עניין, עם אותה תקרה,
  כך שאין העדפה מובנית לידיעה שלילית. סגירה מלאה של קו לשדה התעופה, תערוכה גדולה ואטרקציה חדשה
  מגיעות לראש. שיבוש קטן בקו שולי נשאר למטה.
* **תור** (`ledger.py`): כל פריט נשמר עם סטטוס: ממתין להחלטה, מחוץ למכסה, נפסל לפי הכללים, אושר, נדחה, יצא מהתור.
  פריט ממתין תופס מקום עד החלטה או תפוגה, ולכן ריצה חוזרת על אותם נתונים לא מוסיפה דבר.
  כשמתפנה מקום, הפריטים שחיכו עולים לפי עדיפות ומסומנים "חיכה בתור", לא "חדש".
  עדכון מהותי לפריט שכבר הוצג חוזר תמיד, עם רשימת השינויים. פריט בעדיפות 55 ומעלה נכנס גם לתור מלא, עד 2 בריצה.

## מבנה

| קובץ | תפקיד |
|---|---|
| `run.py` | נקודת ההרצה היחידה |
| `fetch.py` | רשת לקריאה בלבד, robots.txt, בלי עקיפת חסימות |
| `sources/` | מתאם לכל מקור |
| `model.py` | מודל המועמד ושדותיו |
| `dates.py` | פענוח תאריכים עם evidence |
| `factcheck.py` | כל עובדה חייבת להופיע בטקסט המקור |
| `scoring.py` | כשירות לפי כללים, שערי פסילה ועצירה |
| `priority.py` | סדר עדיפויות לפי השפעה על מטיילים |
| `ledger.py` | זיכרון התור בין ריצות והחלטות בעלים |
| `drafts.py` | טיוטות ודוח |
| `config.py` | כל הספים והמילונים |
| `../whats_new_dedup.py` | `classify()`: חדש, עדכון, ביטול, כפילות, פג תוקף. `check()` לא השתנה |
