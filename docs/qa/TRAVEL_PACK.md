# Travel Pack, Phase 1 (local prototype)

Branch `travel-pack-prototype`, on top of the Phase 0 print fix (branch `planner-print-fix-2026-10-04`,
commit 73a7450). NOT for production. The first combined attempt is kept unchanged on `travel-pack-phase-0-1`.

## Route code, the single route representation
`route-code.js` holds the only encode / decode of a route (`/t/<code>`): ordered days, separated by `.`,
each day the 2-character place codes in order (`build_plan_codes.py`, codes never change).
Browser: `window.GoLondonRouteCode`. Node: `require('./route-code.js')`.
Empty days are dropped before numbering (`normalizeDays`), so every output numbers days 1..n.
`node docs/qa/route-code-test.js` compares it with the pre-extraction functions (15,350 comparisons).

## Phase 0, Planner print
`node docs/qa/print-harness.js [--root <site>]` prints automatic, manual and shared routes (1, 3, 7 days)
and checks route content, day numbering, community form absent, hours/prices note present, map links,
no controls printed, and that WhatsApp, Copy and the `/t/` link agree on day numbering.

## Phase 1, Travel Pack prototype
`travel-pack.html?p=<route code>` builds the A4 document from the same route code:
cover (brand, title, days, stops, QR to the live `/t/` route), one page per day (map, numbered stops,
practical details, links), final note (live link, hours/prices disclaimer).

Map = two layers:
- background: replaceable, gets only center, zoom and size (`GoLondonMapBackground.render(view)`).
- overlay (`travel-pack/map-overlay.js`, GoLondon owned): numbered pins, visiting-order line, approximate
  pins (hollow, dashed ring), duplicate points (one pin `n·m`), touching pins (moved, leader line),
  long segments (marked as travel), scale bar, north arrow. Edge cases: `node docs/qa/map-overlay-test.js`.

`travel-pack/prototype-background.js` is a TEMPORARY test background (grid and a hand-typed schematic
Thames, no map data, no network). It must be replaced by the chosen provider before any production use.

Render and QA locally: `node docs/qa/travel-pack-render.js [--code ADAGAEAPANAM] [--out <dir>]`.

## Locked decisions for the next design pass (4 Oct 2026)

**A. No dedicated final page.** The separate, mostly empty "לפני שיוצאים" page goes away. The hours/prices
disclaimer, the live route link, the map attribution and the "generated by GoLondon" note become one
compact closing block (about 20 mm) at the foot of the last day page. Never add an empty closing page.
Page count target:
- 1-day route: 2 pages (cover/overview + day page).
- N-day route: 1 + N pages. A day page holds about 6 to 7 stops with the 84 mm map (6 stops filled 88%
  of the page in the prototype). A longer day may flow onto a second page, breaking only between stops.
- If the closing block does not fit under the last day, it may take the last day's map height down a
  step rather than create a new page.

**B. Cover with purpose.** Keep it calm, no decorative filler. Use the space for what helps planning:
trip summary (days, stops, areas), the day overview (one line per day with area and stop count), the
book-ahead count with the names of the places that need booking, and the QR/live-route block.

**C. Logo.** `images/logo.png` (172 x 96) is too small for print and is not upscaled. The repository already
has `images/originals/logo.png`, 600 x 334 px, the same artwork: about 450 dpi at the current 34 mm cover
width, print quality up to about 50 mm wide at 300 dpi. Use it for the pack. No vector logo exists in the
repository: a vector (SVG or PDF) GoLondon logo is an asset requirement for any larger use. The logo
itself is not redesigned.

**D. Day page.** Keep: large visual map, numbered pins that match the stop list, exact vs approximate
pins, stop details below, direct navigation call to action. The prototype background stays TEST ONLY.

**Map provider.** Geoapify is pending written licensing confirmation. No account or key yet.
